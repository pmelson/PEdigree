# train.py

Train a LightGBM multi-class classifier to identify Windows PE malware families from extracted features.

## Overview

`train.py` reads a directory of NDJSON feature files (one per malware family), preprocesses the data, performs a stratified train/validation/test split, trains a LightGBM classifier with early stopping, evaluates it on the held-out test set, and saves the model artifact plus diagnostic plots.

The trained model artifact is consumed directly by `predict.py` and `tune.py`.

## Prerequisites

- One or more `.json` files in the data directory, each in NDJSON format (one feature record per line).
- Feature files are generated by `extract_features.py`.
- The filename (without extension) is used as the family label when the data does not contain a `label` column.

### Data directory layout

```
data/
├── mirai.json          # all Mirai samples → label "mirai"
├── wannacry.json       # all WannaCry samples → label "wannacry"
├── benign.json         # clean files → label "benign"
└── ...
```

Each `.json` file is NDJSON (newline-delimited JSON): one complete feature record per line, as produced by `extract_features.py`.

## Usage

```bash
# Use defaults (data from current directory, output to ./output/)
python train.py

# Specify data and output directories
python train.py --data-dir ./data/ --output-dir ./models/run1/
```

## Arguments

| Argument | Default | Description |
|---|---|---|
| `--data-dir` | Script directory | Directory containing `.json` NDJSON family files |
| `--output-dir` | `./output/` | Directory where all output artifacts are written |

## Outputs

All files are written to `--output-dir`:

| File | Description |
|---|---|
| `malware_classifier.pkl` | Serialized model artifact (see below) |
| `classification_report.txt` | Per-class precision, recall, F1, and macro-F1 on the test set |
| `confusion_matrix.png` | Row-normalized confusion matrix heatmap |
| `feature_importance.png` | Bar chart of the top 30 features by LightGBM gain importance |

### Model artifact (`malware_classifier.pkl`)

The `.pkl` file is a Python dict with the following keys:

| Key | Type | Description |
|---|---|---|
| `model` | `LGBMClassifier` | Trained LightGBM model |
| `label_encoder` | `LabelEncoder` | Maps family name strings ↔ integer class indices |
| `feature_cols` | `list[str]` | Ordered list of feature column names used during training |
| `cat_encoders` | `dict` | Per-column `LabelEncoder` instances for categorical features |
| `macro_f1` | `float` | Macro-averaged F1 score on the test set |

## Train / Validation / Test Split

The data is split **70% train / 15% validation / 15% test** using stratified sampling so that class proportions are preserved across all three sets.

**Rare class handling:** any family with fewer than 10 samples cannot be reliably stratified. Such families are placed entirely in the training set and excluded from validation and test evaluation.

## Preprocessing

Before training, the following transformations are applied:

- Non-feature columns (`file_path`, `parse_error`, `imphash`, `label`) are dropped.
- Categorical columns (`machine_type`, `subsystem`, `entry_section_name_is_standard`) are label-encoded to integers.
- Any remaining non-numeric columns are label-encoded.
- Missing numeric values (NaN) are filled with **−1**, a sentinel meaning "field not present in this PE file".

These same transformations are reproduced at inference time by `predict.py`.

## Training Details

- **Algorithm**: LightGBM multi-class classifier
- **Early stopping**: training halts when validation `multi_logloss` does not improve for 50 consecutive rounds (up to 1000 estimators)
- **Class weights**: `balanced` — automatically up-weights under-represented families
- **Random seed**: 42 (reproducible splits and model)

## Notes

- Re-running `train.py` on the same data with the same seed produces an identical model.
- `tune.py` performs hyperparameter search over the same data and produces `malware_classifier_tuned.pkl`, which `predict.py` prefers over the baseline artifact from `train.py`.
- Families present in training but absent from the test set are omitted from the classification report but do not cause errors.
